What you build

ResourceNamePurpose
VPClab1-customIsolated network with public subnets and an Internet Gateway
Security groupSGAAllows HTTP and SSH from anywhere
Security groupSGBAllows HTTP, SSH, and ping (ICMP) from SGA
EC2 instanceInstance-AApache web server, uses SGA
EC2 instanceInstance-BApache web server, uses SGB

You need an AWS account and a key pair (or EC2 Instance Connect). Everything fits in the Free Tier as long as you skip the NAT gateway.

Steps

  1. Create the custom VPC

    In the VPC console choose Create VPC, then VPC and more. Name it lab1-custom and select no NAT gateway. Afterwards, turn on auto-assign public IPv4 for the public subnets.

  2. Create SGA and SGB

    Create SGA first (HTTP and SSH from anywhere). Then create SGB with the same two rules plus All ICMP - IPv4 from SGA.

  3. Launch the instances

    Amazon Linux, t2.micro, a public subnet, public IP enabled. Paste the script below into User data. Use SGA for Instance-A and SGB for Instance-B.

    #!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd

  4. Test the baseline

    Open each public IP in a browser. Connect with EC2 Instance Connect. Run ping from A to B's private IP. Run curl from B to A's public IP. All four should work.

  5. Change the rules and test again

    Change 1
    Limit SGA HTTP to YOUR_IP/32. Your home Wi-Fi still loads the page. A mobile hotspot times out, and so does curl from Instance-B.
    Change 2
    Add a NACL inbound deny rule for your IP, numbered 90. It must be lower than the default allow rule (100) because the lowest matching number wins. The page now fails even though SGA allows you.
    Change 3
    Limit SGB HTTP to SGA as the source. Browsers can no longer reach Instance-B. Curl from Instance-A works, but only when you use B's private IP.

Rules at a glance

ItemStartAfter Change 1After Change 3
SGA, HTTP 800.0.0.0/0Your home IP /32Same as Change 1
SGA, SSH 220.0.0.0/0UnchangedUnchanged
SGB, HTTP 800.0.0.0/0UnchangedSource is SGA
SGB, ICMPSource is SGAUnchangedUnchanged
Subnet NACLDefault, allow allUnchangedUnchanged
  • Security groups only allow traffic. NACLs can allow or deny.
  • Security groups are stateful. NACLs are stateless and are checked first, at the subnet boundary.
  • A rule that names a security group matches private addresses only, so test with the private IP.

Troubleshooting

ProblemLikely cause and fix
Browser shows nothingThe URL uses https://, or Apache has not started. Use http:// and check that the User data ran.
No public IP on the instanceAuto-assign was off. Turn it on for the subnet, or relaunch with Auto-assign public IP set to Enable.
Ping from A to B failsCheck that SGB has the ICMP rule with SGA as source, and use B's private IP.
NACL deny does nothingIts rule number is higher than the allow rule. Use a lower number such as 90.
Locked out after Change 1Your home IP has changed. Update the SGA rule with your current IP.

When you finish, terminate both instances, delete the lab1-custom VPC, then delete SGA and SGB.
